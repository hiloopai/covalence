Struct S3Kv

Expand description

A store under an S3 location, using path-style requests (<endpoint>/<bucket>/<key>).

§Keys

A key is stored as the object <prefix><key>. Keys must be non-empty UTF-8 whose /-separated segments are non-empty and not . or .., since request URLs would rewrite them: a/b is a key, but a//b, /a, a/ and a/../b are not. Other keys fail with Error::Key, though other stores such as MemoryKv accept them.

§Writes

  • A value of up to the part size (PART unless set with S3Kv::part_size) is written with one PUT.
  • A larger value is written with a multipart upload, in parts of the part size, or larger parts if needed to keep to S3’s limit of 10,000 parts.
  • Each PUT or part sends the SHA-256 of its body as x-amz-checksum-sha256, which S3 checks against the bytes it receives.
  • A failed multipart upload is aborted once its parts in flight finish. If aborting fails too, the error is Error::Abort.

§Reads

  • Values are read with ranged GETs of the part size. The first gives the value’s size and ETag; a value larger than one part must have an ETag.
  • Every later range must report the same size and ETag, or the read fails with Error::Changed, so the bytes all come from one value.
  • A server may ignore Range and send the whole value. That works for a value of up to the part size; for a larger one the read fails.
  • [Kv::size] and [Kv::exists] use HEAD; [Kv::get_range] uses one ranged GET.

§Requests

  • Up to CONCURRENCY parts or ranges (unless set with S3Kv::concurrency) move at once, each on its own thread, while the reader or writer sees the bytes in order.
  • A request is tried up to 4 times, waiting 0.5, 1 and 2 seconds between attempts, when it gets status 429 or 5xx, or fails to complete for a reason other than a bad URL or an oversized response body.
  • Each attempt may take 30 seconds, plus a second per MiB of the body it sends or may receive (per part, when completing a multipart upload).
  • Redirects are not followed: the request fails with Error::Status.

Every request blocks: the async methods finish theirs before returning a ready future, so do not await them on an async runtime thread.

use covalence_kv_s3::{AwsOptions, S3Kv};
use covalence_kv_trait::Kv;
let store = S3Kv::from_aws("s3://example/packs/".parse()?, &AwsOptions::default())?;
if let Some(size) = store.size(b"pack")? {
    let prefix = store.get_range(b"pack", 0, size.min(1024))?;
    // A missing key is None; an empty or exhausted range is empty bytes.
    if let Some(prefix) = prefix {
        assert!(prefix.len() <= 1024);
    }
}

pub fn from_aws( location: S3Location, options: &AwsOptions, ) -> Result<Self, Error>

A store for location, configured as the AWS SDKs are.

  • Profile: options.profile, else AWS_PROFILE, else default.
  • Region: options.region, else AWS_REGION, AWS_DEFAULT_REGION, the profile, or EC2 instance metadata, in that order; else Error::Region.
  • Endpoint: AWS_ENDPOINT_URL or the profile’s endpoint_url, else https://s3.<region>.amazonaws.com, or .amazonaws.com.cn for a region starting cn-. Other partitions need AWS_ENDPOINT_URL.
  • Credentials: the SDKs’ default chain (environment variables, profile files including SSO and credential_process, web identity, ECS and EKS Pod Identity, EC2 instance roles), or with options.profile only that profile’s settings (which may name another profile or a credential_source).

Credentials are fetched at the first request, and again when they are within 5 minutes of expiring. Finding the region may query instance metadata, which takes a moment off EC2 unless a region is set. This may be called inside an async runtime, though it blocks.

fn get_range( &self, key: &[u8], start: u64, len: u64, ) -> Result<Option<Bytes>, Error>

Fetch a single range using a signed Range header.

  • Follows [Kv::get_range], including its missing/empty/EOF rules.
  • A zero-length range asks HEAD, to tell a missing key from an empty range.
  • Validates Content-Range and the partial body length.
  • Limits the reply to len.
  • A whole-value 200 reply is sliced, if it is within that limit.
  • Servers reject offsets past i64::MAX: a start past it asks HEAD, as an empty range does, and an end past it is clipped to it.
  • Rejects larger or differently positioned replies; no full-fetch fallback.
