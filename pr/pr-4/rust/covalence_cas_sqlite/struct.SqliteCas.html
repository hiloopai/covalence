Struct SqliteCas

Expand description

A store in SQLite.

The database has three tables:

  • blobs: one row per block, its bytes inline in data when storage is empty. Reading a row with other storage fails with a backend error.
  • hashes: maps a digest and its hash function’s multicodec code to a block. Every block has a BLAKE3 row, and a SHA-256 row when indexed. Other hashes, such as the SHA-1 of Git objects, fit the same table.
  • meta: the Sha256Policy and the database’s id.

Reads and writes:

  • A BLAKE3 or SHA-256 CID with any codec finds its bytes, if it has the row; [Put] over [Cid] returns the raw BLAKE3 CID.
  • Rows can be corrupted on disk, so get checks the bytes it returns against the requested hash, whichever row found them; get_unchecked, sizes and ranges do not.
  • Sizes and ranges read only the bytes they need from the block.
  • has consults the hash index and block metadata, without loading or checking the bytes.
  • Puts hash in Rust. The SQL function hash(code, data), registered on the store’s connection, serves only SqliteCas::index_sha256 and SqliteCas::verify: it never decides what a read checks.
  • [Cas::info] is {"name": "sqlite", "id": <hex id or null>}; [Cas::stats] counts blocks and the bytes of inline data.

One connection, behind a mutex, serves every caller. Files use SQLite’s write-ahead log (journal_mode = WAL) with synchronous = NORMAL. The async methods call the sync ones, so they block.

fn has(&self, key: &Cid) -> Result<bool, Error>

Check the hash index and block storage without reading the payload.

  • BLAKE3 and indexed SHA-256 CIDs match regardless of codec.
  • Missing keys, unsupported hashes and dangling index rows return false.
  • Payload corruption is not checked; unknown storage is a backend error.

Reads no further; stores nothing and fails with [Error::Check] if the bytes have another CID, or with [Error::Io] if reader fails or ends early. Reads them into memory by default; stores that can stream override it.

Fails with [Error::Check] if they do not match key, or with [Error::Io] if writer fails; after a failure writer may hold unchecked bytes, so discard them. Writes [GetExt::get_fact] by default; stores that can stream override it.
