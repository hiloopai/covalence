The content-addressed storage traits.

A content-addressed store (CAS) keeps blocks of bytes under keys computed from the bytes. Keys are usually CIDs: a CID names a hash function, the hash’s digest of the bytes, and a codec saying how to read them. A [Fact] is bytes checked to hash to a CID’s digest.

  • DASL (Data-Addressed Structures & Links) is a small set of specs for content-addressed data: CIDs, and DRISL for structured values. A DASL value here is null, a boolean, an integer, bytes, a string, a list, a map with string keys, or a CID link.
  • DRISL is DASL’s deterministic CBOR encoding, so equal values encode to equal bytes and get equal CIDs.

Each operation is its own trait, generic over the key type, so a store can answer several key types:

  • Get and Put are sync; AsyncGet and AsyncPut are their async twins. As in Python, each async method is its sync name prefixed with a: get and aget, put and aput.
  • Cas combines them over [Cid]. Hold a store as Arc<dyn Cas> (or take &dyn Cas) rather than being generic; Cas::into_dyn makes one.
  • Cas::info and Cas::stats describe a store, for debugging, as a DASL value.
  • Stores live in their own crates, such as covalence-cas-memory.

Reads come at three levels:

  • get_unchecked: the fast path; the store need not check its answer.
  • get: what the store vouches for. Checking means different things for different stores (a table of facts needs none, a remote store hashes), so stores override it; by default it is get_unchecked.
  • get_fact, in GetExt: always checked, and cannot be overridden. It checks that the store’s [Fact] has the key’s hash and digest, then returns it under exactly the key asked for. A fact proves only the hash and digest; the codec says how to read the bytes, so asking for a DRISL CID gives a fact for that DRISL CID, however the store keeps the bytes.

AsyncGet and AsyncGetExt mirror these.

Sizes and byte ranges come at the first two levels, as size_unchecked and get_range_unchecked, and size and get_range. By default they fetch the whole value and measure or slice it; stores with native ranges override them. Nothing in these traits checks a size or a range against its key, as get_fact checks bytes.

Cas::put_from and Cas::get_to move a block between the store and a reader or writer, checked; by default they hold it in memory, and stores that can stream override them.

A store needs only get_unchecked, aget_unchecked, put and aput; the defaults supply the rest. Here a store answers with corrupted bytes: get passes them on, as it does by default, but get_fact catches them.

use std::{collections::HashMap, sync::RwLock};

use covalence_cas_trait::{
    AsyncGet, AsyncPut, Cas, CasFuture, Error, Get, GetExt, Put, ready,
};
use covalence_lib_cid::{Blake3, Cid};
use covalence_lib_data::Bytes;

#[derive(Default)]
struct Map(RwLock<HashMap<Cid, Bytes>>);

impl Get for Map {
    fn get_unchecked(&self, key: &Cid) -> Result<Option<Bytes>, Error> {
        Ok(self.0.read().unwrap().get(key).cloned())
    }
}
impl AsyncGet for Map {
    fn aget_unchecked<'a>(&'a self, key: &'a Cid) -> CasFuture<'a, Option<Bytes>> {
        ready(self.get_unchecked(key))
    }
}
impl Put for Map {
    fn put(&self, bytes: Bytes) -> Result<Cid, Error> {
        let key = Blake3::of(&bytes).into();
        self.0.write().unwrap().insert(key, bytes);
        Ok(key)
    }
}
impl AsyncPut for Map {
    fn aput(&self, bytes: Bytes) -> CasFuture<'_, Cid> {
        ready(self.put(bytes))
    }
}
impl Cas for Map {}

let store = Map::default();
let cid = store.put("hello".into())?;
assert_eq!(store.size(&cid)?, Some(5));
assert_eq!(store.get_range(&cid, 1, 3)?.unwrap(), "ell");
assert_eq!(store.get_fact(&cid)?.unwrap().bytes(), "hello");

store.0.write().unwrap().insert(cid, "jello".into());
assert_eq!(store.get(&cid)?.unwrap(), "jello");
assert!(matches!(store.get_fact(&cid), Err(Error::Check { .. })));
