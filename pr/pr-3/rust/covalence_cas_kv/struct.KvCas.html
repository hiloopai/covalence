Struct KvCas 

Source 
pub struct KvCas { /* private fields */ }
Expand description

A store of blocks in a [Kv]; see the crate docs for the key layout.

  • A CID with a 32-byte BLAKE3 digest finds its bytes whatever its codec; other CIDs find nothing. [Put] returns the raw BLAKE3 CID.
  • The key-value store may be remote or shared, so get, aget, get_fact and aget_fact check the bytes against the CID and fail with [Error::Check] if they do not match. get_unchecked, sizes and ranges are not checked.
  • has asks the key-value store whether the key exists, without reading the bytes.
  • put, aput and put_from never replace a block: they store through the key-value store’s [Kv::put_new], [Kv::aput_new] and [Kv::put_new_from], so concurrent writers of one block race safely. Writes fail if the backend does not implement atomic create-only writes.
  • put_from and get_to stream through the key-value store’s own put_new_from and get_to, hashing the bytes as they pass. If the backend skips an existing block, put_from returns without consuming or checking any remaining input.
  • If the bytes put_from reads do not hash to the CID, the read that would hand over the last byte fails instead. The key-value store’s put_from then fails as [Kv::put_from] says, storing nothing, and put_from fails with [Error::Check]; or with [Error::Backend] if the key-value store reports a further failure, such as failing to clean up.
  • [Cas::info] is {"name": "kv", "prefix": <prefix>, "kv": <the key-value store's info>}; [Cas::stats] is the key-value store’s.

§S3

Writes use conditional requests to preserve existing blocks. They do not make a preliminary HEAD request, so they need only write access.

has uses a HEAD request. S3 answers a HEAD for a missing key with 403 to a client that may not list the bucket.

S3 may consume the source before discovering that a block already exists. Once the backend skips insertion, put_from leaves any remaining input unread.

pub fn with_prefix(kv: Arc<dyn Kv>, prefix: &str) -> Result<Self, InvalidPrefix>

A store with keys under prefix/ in kv; a trailing / on prefix is optional.

Fails with InvalidPrefix unless prefix is /-separated, non-empty segments other than . and .., so the empty prefix fails: use KvCas::new instead.

use covalence_cas_kv::KvCas;
use covalence_kv_memory::MemoryKv;
use covalence_kv_trait::Kv;
let kv = MemoryKv::default().into_dyn();
assert!(KvCas::with_prefix(kv.clone(), "a/b/").is_ok());
for prefix in ["", "/", "/a", "a//b", "a/../b"] {
    assert!(KvCas::with_prefix(kv.clone(), prefix).is_err());
}
